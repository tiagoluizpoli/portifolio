# Section Audit: Impact Metrics (Source-Driven Parity)

## Current Implementation vs Requirement (Iteration 4)

| Feature | Requirement | Current State | Status |
| :--- | :--- | :--- | :--- |
| **ID Strategy** | Appwrite Autogenerated (`ID.unique()`) | Custom prefix (`metric_xxx`) | **VIOLATION** |
| **Icons** | Source-Driven with Manual Override | Hardcoded per Metric | **VIOLATION** |
| **Sync Logic** | Cross-locale Ghost Row generation | Manual entry per locale | **VIOLATION** |
| **Linking** | Parity via `internalCode` | Random UUIDs per row | **VIOLATION** |
| **Constraint** | `(locale, internalCode)` Uniqueness | None in Schema | **VIOLATION** |
| **Telemetry** | Automated vs Manual Sources | Manual values only | **VIOLATION** |

## Required Technical Adjustments

### 1. Unified Normalization Layer
- **`useMetricNormalizer` Hook**: Implement a frontend hook to join `ImpactMetric` records with their `MetricSource` registry metadata.
- **Logic**: `UI_Icon = Metric.iconCode ?? Source.iconCode`.

### 2. Service-Side Sync Engine
- **`syncMetricParityFn`**: Orchestrates the generation of `isPlaceholder: true` ghost rows in alternate locales when a metric is created.
- **Uniqueness Constraint**: Migrator must enforce a unique index on `(locale, internalCode)`.

### 3. Metric Registry
- **Source-Centric Dialog**: `MetricDialog` must dynamically lock the `value` field if an **Automated Source** is selected.
- **Seeding**: Infrastructure must provide a standard `manual` source with a default icon.

### 4. Telemetry Restoration
- Map automated sources to **Appwrite Functions** via `functionId`.
- Automated sources will be responsible for hydration of the `value` field.
