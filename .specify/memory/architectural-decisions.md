# Architectural Decision Log: Zenith CMS

This document records the core architectural decisions for the Zenith Portfolio CMS, tracking the rationale, status, and implications of key design shifts.

## AD-001: Source-Driven Metric Identity
**Date**: 2026-04-13  
**Status**: Approved  
**Tags**: #architecture #metrics #data-model

### Context
Impact Metrics were previously storing visual (Icon) and logic (Telemetry) data redundantly within each localized record. This caused synchronization overhead and UI inconsistency.

### Decision
Transition to a **Source-Driven** model where visuals and telemetry logic are centralized in a `MetricSource` entity.

1.  **ID Strategy**: Use Appwrite autogenerated IDs (`ID.unique()`) for all entities.
2.  **Visuals**:
    - Icons are defined at the `MetricSource` level.
    - `ImpactMetric` records can optionally override the source icon via `iconCode`.
    - **Logic**: `UI_Icon = ImpactMetric.iconCode ?? MetricSource.iconCode`.
3.  **Telemetry**:
    - `MetricSource` has a `type` (manual/automated) and an optional `functionId`.
    - **Manual**: Value is populated via user input in the CMS.
    - **Automated**: Value is hydrated by a server-side Appwrite function linked to the `functionId`.
4.  **Parity & Uniqueness**:
    - Enforcement of a unique index on **`(locale, internalCode)`** in the `ImpactMetric` collection.
    - `internalCode` acts as the cross-locale semantic anchor.

### Consequences
- Reduced database row size for metrics.
- Simplified cross-locale synchronization (Parity logic).
- Centralized management of automated telemetry sources.
